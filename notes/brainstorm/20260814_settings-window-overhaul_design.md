# Switchboard 설정창 전면 개편 UX 설계

상태: 사용자 방향 승인 완료, 구현 승인 대기

작성: 2026-08-14

시각 목업: [`settings-window-overhaul-interactive.html`](settings-window-overhaul-interactive.html)
근거 보강: [`settings-window-overhaul-20260814-0121.md`](../auto-brief/settings-window-overhaul-20260814-0121.md)

## 1. 한 줄 목표

Switchboard 사용자가 화면 전환창을 원하는 자리에 드래그해 영구적으로 두고, 별도 설정창에서 모양·크기·동작을 한눈에 관리하도록 만든다.

## 2. 문제

- 사용자는 전환창을 자기 작업 흐름에 맞는 자리로 두고 싶지만, 현재 앱은 레이아웃을 계산할 때마다 5개 프리셋 위치로 다시 배치한다.
- 현재 설정은 헤더에 붙은 386px 팝업 안의 긴 세로 목록이라, 항목 관계를 파악하기 어렵고 "위치 이동"과 "영구 기본 위치"의 의미가 섞여 있다.
- 근거: 현재 `MainWindow.xaml`의 앵커형 `Popup`, `ApplyContentSizedBounds()`의 프리셋 재배치, 사용자 요구와 승인된 목업.
- 해결하지 않으면 사용자가 매번 위치를 되돌려야 하고, 전환창을 개인 작업 흐름에 맞추는 핵심 이점이 사라진다.

이 막힘은 8번의 "드래그한 위치가 재실행·크기 변경 뒤에도 예측 가능하게 복원된다" 지표와 직접 짝을 이룬다.

## 3. 사용자와 맥락

- 사용자: 여러 창을 빠르게 전환하며, 화면 한쪽의 작업 공간을 아끼려는 Windows 11 사용자.
- 맥락: Alt+Tab 또는 전역 단축키로 짧게 오버레이를 열며, 설정은 가끔 열어 정리한다.
- 제약: 오버레이는 일반 창 선택을 방해하면 안 되고, 카드·검색·버튼 클릭은 현재와 같은 방식으로 작동해야 한다. 고해상도/작은 화면 및 모니터 구성 변경에도 창이 화면 밖으로 사라지면 안 된다.

## 4. 사용자 여정

| 단계 | 사용자 행동 | 생각·감정 | 막히는 점 | 개선 아이디어 |
|---|---|---|---|---|
| 1 | 전환창을 열고 작업 공간에 맞는 자리로 옮기려 한다 | "여기에 항상 있었으면 좋겠다" | 현재 위치는 프리셋으로 덮어써진다 | 빈 배경 드래그 종료 시 위치를 즉시 저장 |
| 2 | 톱니를 눌러 표시 방식을 바꾼다 | "위치와 크기를 어디서 바꾸지?" | 작은 팝업의 긴 목록에서 항목 관계가 흐리다 | **별도 설정창의 왼쪽 사이드바로 목적별 탭을 나눈다** |
| 3 | 한 번만 화면 모서리로 옮기고 싶다 | "기본 자리는 건드리지 말자" | 프리셋 선택이 영구 기본 위치도 바꾼다 | 그림 리모컨은 일회성 이동만 하고 저장 위치는 유지 |
| 4 | 배율이나 보기 모드를 바꾼다 | "모서리에 둔 자리는 그대로여야 한다" | 크기 변화 뒤 기준점이 불분명하다 | 가까운 모서리·가장자리·중앙 기준으로 확장·복원 |

설정창을 닫으면 사용자는 기존 전환창으로 돌아가며, 변경 사항은 이미 저장되어 다음 실행에도 적용된다.

## 5. 핵심 흐름

### A. 설정 열기와 닫기

1. 사용자가 오버레이 헤더의 설정 버튼을 누른다.
2. 오버레이 소유의 별도 설정창이 중앙에 모달로 열린다.
3. 기본 탭은 `위치와 이동`이다. 왼쪽 탭을 누르면 오른쪽 콘텐츠 전체가 해당 목적의 화면으로 전환된다.
4. 변경은 즉시 적용·저장된다. 적용/저장 버튼은 두지 않는다.
5. `X` 또는 `Esc`를 누르면 설정창만 닫고 오버레이는 계속 보인다. 설정창이 열려 있는 동안 오버레이의 카드 선택·검색·단축키 입력은 받지 않는다.

### B. 직접 드래그하여 영구 위치 저장

1. 사용자는 헤더·콘텐츠의 빈 배경·목록의 빈 여백에서 왼쪽 버튼을 누르고 드래그한다.
2. 카드, 카드의 닫기 버튼, 검색 상자, 설정 버튼, 토글, 스크롤바, 콤보박스 등 상호작용 요소에서 시작한 동작은 드래그가 아니라 기존 입력으로 처리한다.
3. 드래그가 끝나면 현재 모니터 작업 영역에서 가장 가까운 3×3 기준점과 그 기준점으로부터의 여백을 계산한다.
4. 이 위치를 즉시 JSON 설정에 저장한다.
5. 다음 표시, 보기 모드 변경, 배율 변경 때는 저장된 기준점과 여백으로 위치를 다시 계산하고 화면 안으로 보정한다. 이 재계산은 저장값을 덮어쓰지 않는다.

### C. 위치 리모컨의 일회성 이동

1. `위치와 이동` 탭의 3×3 그림에서 원하는 방향을 누른다.
2. 전환창은 해당 화면의 좌상/상단/우상/좌측/중앙/우측/좌하/하단/우하 중 하나로 즉시 이동한다.
3. 열 번째 행동인 `저장한 위치로 돌아가기`는 마지막 드래그 저장 위치를 복원한다.
4. 이 리모컨 동작은 영구 위치를 저장하지 않는다. 사용자가 그 결과 위치에서 드래그를 끝냈을 때만 새 기본 위치가 된다.

### D. 화면 구성 변경 뒤 복원

1. 저장된 모니터가 있으면 그 작업 영역 안에서 복원한다.
2. 저장된 모니터를 찾을 수 없거나 창 전체가 보이지 않으면 주 모니터 작업 영역으로 옮기고, 최소 여백을 지키며 완전히 보이도록 보정한다.
3. 창이 커졌을 때는 사용자가 선택한 첫 번째 원칙대로 가까운 가장자리·모서리를 유지한다. 예: 우하단 기준이면 우하단을 붙잡고 좌상 방향으로 확장한다.

## 6. 화면 / 출력 의도

### 전환창

- 핵심 행동: 빈 공간을 드래그해 영구 위치를 정한다.
- 1순위 정보: 창 카드와 선택 상태. 2순위: 검색·보기·정렬·설정. 3순위: 이동 가능성은 별도 안내 없이 자연스러운 빈 배경 드래그로 제공한다.
- 헷갈릴 점 방지: 카드와 모든 조작 요소는 드래그 시작 대상에서 제외한다. 빈 목록 여백은 드래그 가능하다.

### 설정창: 공통 틀

- 핵심 행동: 왼쪽 탭으로 설정 목적을 고르고 오른쪽에서 바로 바꾼다.
- 1순위 정보: 현재 탭 제목과 한 줄 설명. 2순위: 해당 탭의 조작 요소. 3순위: "변경 내용 저장됨" 상태와 닫기.
- 설정창은 소유 오버레이 중앙에 열리며, 창 프레임은 오버레이와 같은 차분한 색·8px 이하 카드 모서리·절제된 그림자를 쓴다.

### `위치와 이동` 탭

- 핵심 행동: 저장된 위치를 이해하고, 드래그 저장 또는 리모컨 이동을 구분해 사용한다.
- 1순위 정보: `드래그하면 자동 저장` 설명과 현재 저장 위치. 2순위: 화면 그림 3×3 리모컨. 3순위: `저장한 위치로 돌아가기`.
- 리모컨의 10개 행동: 9방향 그림 + 저장 위치 복귀. 각 방향은 짧은 한국어 레이블과 화면 안 작은 창 그림을 함께 표시한다.
- 헷갈릴 점 방지: 리모컨 아래에 "한 번 이동 — 기본 위치는 바뀌지 않음"을 상시 표기한다.

### `모양과 크기` 탭

- 핵심 행동: 전체 배율을 선택하고 즉시 적용된 미리 보기를 확인한다.
- 1순위 정보: `60 / 70 / 80 / 100 / 125 / 150 / 200%` 전체 배율. 2순위: 화면 분위기와 미리 보기 크기. 3순위: 각 항목의 짧은 설명.
- 헷갈릴 점 방지: 전체 배율은 글자·카드·간격을 함께 바꾸며, 미리 보기 크기는 카드 안 미리 보기만 바꾼다는 설명을 분리한다.

### `기본 동작` 탭

- 핵심 행동: 항상 위, 컴팩트 보기, 기본 보기, 크기 정책, 단축키를 조절한다.
- 1순위 정보: 항상 위/컴팩트 보기. 2순위: 기본 보기·크기 정책. 3순위: 단축키 조합.
- 헷갈릴 점 방지: 단축키 충돌 피드백은 이번 설계의 후속 과제로 명시한다.

## 7. 우선순위

- 안 하는 것(2개): 자동 창 배치·창 크기 조절 추가, 가상 데스크톱별 위치·모니터별 독립 프로필 관리, 리모컨 클릭의 영구 위치 저장. 이들은 사용자가 직접 위치를 정한다는 이번 목표를 흐리거나 작업 공간 관리 범위를 새로 만든다.

| 구분 | 내용 |
|---|---|
| **안 함** | 자동 창 배치나 창 크기 조절을 추가하지 않는다. 사용자가 정한 위치를 대신 판단하는 기능은 요구와 반대다. |
| **안 함** | 가상 데스크톱별 위치, 모니터별 독립 프로필 관리, 창 배치 이력을 만들지 않는다. 현재 요구를 넘어선 작업 공간 관리다. |
| **안 함** | 리모컨 클릭을 영구 저장으로 바꾸지 않는다. 직접 드래그만 기본 위치를 바꾼다는 구분을 지킨다. |
| Must | 별도 모달 설정창, 3개 사이드바 탭, 빈 배경 드래그 저장, 10개 리모컨 행동, 60/70% 유효 배율, 화면 안 복원 보정. |
| Should | 현재 저장 위치 표시, 설정값 즉시 저장 표시, 다중 모니터 제거 시 주 모니터 폴백, 60~200%에서 설정창 스크롤·크기 보정. |
| Could | 마지막 리모컨 이동 상태 표시, 위치 초기화 버튼, 더 자세한 단축키 충돌 안내. |

## 8. 성공 지표

- 핵심 지표: 새로 저장한 드래그 위치가 앱 숨김/재표시와 앱 재실행 뒤에도 같은 작업 영역 기준으로 복원된다.
- 예측 가능성: 우하단·좌상단·중앙에 저장한 창이 60/70/100/200%와 Grid/Compact/List 전환 뒤에도 해당 기준점을 유지하고 화면 밖으로 나가지 않는다.
- 구분성: 리모컨 9방향과 저장 위치 복귀를 사용해도 JSON의 영구 위치는 변하지 않으며, 드래그 종료 때만 변한다.
- 사용성: 설정창의 세 탭에서 기존 설정 항목을 모두 찾을 수 있고, 기존 카드·검색·버튼 조작이 드래그로 오인되지 않는다.

| 누가·언제 | 구현자와 사용자가 구현 직후 동일 작업 공간에서 확인한다. |
| 자동 검증 | Core 위치 계산: 9개 앵커, 기준점 여백, 크기 변경, 경계 보정, 저장 모니터 폴백. App 설정: JSON 왕복, 구 프리셋 마이그레이션, 60/70% 목록·정규화, 리모컨이 저장값을 바꾸지 않는지. |
| 빌드 검증 | `dotnet build Switchboard.slnx --nologo`, `dotnet test Switchboard.slnx --nologo`. |
| 실제 UI 검증 | 60/70/100/200%와 Grid/Compact/List에서 드래그 저장·재실행 복원·9방향 리모컨·복귀 버튼·X/Esc·카드/검색 클릭을 확인한다. 저장 모니터를 제거한 상태는 가능하면 실제 또는 안전한 화면 구성 변경으로 확인한다. |

| Plan C | 다중 모니터 식별이 구현 환경에서 신뢰롭지 않으면, 이번 릴리스는 주 모니터 작업 영역 안 완전 가시 보정으로 안전하게 폴백하고 모니터별 정확 복원을 후속으로 기록한다. |

## 완료 규율

- Finish Line: 별도 설정창의 세 탭에서 모든 기존 설정을 조작할 수 있고, 드래그 위치 저장·10개 리모컨·60/70%·화면 안 복원이 실제로 동작한다.
- Acceptance Checks: 9번 자동/실제 UI 검증을 통과하고, Release 빌드 경고·오류가 0개다.
- Scope Limit: 이 설계는 설정창 전면 개편과 오버레이 위치 저장에 한정한다.
- Review Budget: 구현 후 자동 검증 1회, 실제 UI 점검 1회, BLOCKER에 한해 최대 2회의 수정·재검토 루프를 사용한다.
- Stop Rule: Acceptance Checks가 통과하면 인접 개선(위치 초기화, 모니터별 프로필, 단축키 충돌 안내)은 후속으로 넘긴다.

## 부록 A. 구현 경계와 데이터 계약

### 계층 소유권

- `Switchboard.Core`: 3×3 위치 앵커, 앵커·여백을 현재 작업 영역과 오버레이 크기로 계산하는 순수 위치 계산, 경계 보정 모델과 단위 테스트.
- `Switchboard.Native`: 좌표가 속한 모니터와 해당 작업 영역·장치 식별자를 얻는 Win32 경계. WPF는 새 P/Invoke를 직접 소유하지 않는다.
- `Switchboard.App`: 드래그 시작/종료 판정, 설정 JSON, 별도 `SettingsWindow`, 설정창의 리모컨 클릭, `LocationChanged` 저장 호출, 오버레이와 설정창의 소유·포커스 관계.

### 영구 위치 데이터

새 저장 모델은 다음 의미를 가진다. 정확한 타입명은 구현 계획에서 정한다.

| 필드 | 의미 |
|---|---|
| `MonitorDeviceName` | 저장 당시 작업 영역을 제공한 모니터 식별자. 없거나 찾지 못하면 주 모니터로 폴백한다. |
| `Anchor` | `TopLeft / TopCenter / TopRight / MiddleLeft / Center / MiddleRight / BottomLeft / BottomCenter / BottomRight` 중 가장 가까운 기준점. |
| `OffsetX`, `OffsetY` | 해당 앵커 기준으로부터의 실제 여백. 임의 드래그 위치를 정확히 유지한다. |

계산은 현재 오버레이 크기를 반영한 앵커의 기준 좌표에 여백을 더한 뒤, 현재 작업 영역 안으로 보정한다. 우측/하단 앵커는 창의 우측/하단 변을 기준으로 잡으므로 크기가 커져도 그 가장자리에서 멀어지지 않는다.

### 기존 설정 호환

- 기존 `CompactOverlayPlacement`는 새 영구 위치가 없는 구 설정 파일의 첫 복원에만 사용한다. 기존 5개 값은 같은 이름의 3×3 앵커로 옮기고, 기존 18px 여백을 적용한다.
- 사용자가 최초로 드래그를 끝내면 새 위치 데이터가 저장되며 이후에는 구 프리셋이 자동 배치에 참여하지 않는다.
- `OverlayScalePreset`에는 `Sixty`를 추가하고 기존 `Seventy`를 정상 선택지로 되살린다. 유효 목록은 `60/70/80/100/125/150/200%`다.
- 기존 레거시 값은 `Fifty → Sixty`, `Ninety → Hundred`, `OneTwenty → OneTwentyFive`로 한 번 정규화한다. 이미 저장된 `Seventy`는 80%로 바꾸지 않는다.

### 설정창 구현 규칙

- 현재 `Popup`과 `IsSettingsOpen` 기반 UI는 제거하고, 오버레이가 소유하는 재사용 가능한 `SettingsWindow`로 교체한다.
- 설정창은 `ShowDialog()`로 열고 `Owner`를 오버레이로 지정한다. `ShowInTaskbar=false`, `ResizeMode=NoResize`, `WindowStartupLocation=CenterOwner`, X/Esc 닫기를 제공한다.
- `PresentationScale`은 설정창에도 적용하되 현재 모니터 작업 영역을 넘지 않도록 크기·스크롤 영역을 보정한다. 60~200%에서 사이드바와 본문이 접근 가능해야 한다.
- WPF `DragMove()`는 빈 클라이언트 영역에서만 호출한다. 이벤트 처리 전 상호작용 조상(ButtonBase, TextBoxBase, Selector item, ScrollBar, Thumb, ComboBox 등)을 검사한다.
