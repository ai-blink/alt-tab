# 실행 계획: Switchboard 설정창 전면 개편

상태: 구현 완료 · 실제 UI 점검 대기

설계 근거: [`20260814_settings-window-overhaul_design.md`](../brainstorm/20260814_settings-window-overhaul_design.md)
시각 기준: [`settings-window-overhaul-interactive.html`](../brainstorm/settings-window-overhaul-interactive.html)

## 1. 목표

전환창을 빈 공간에서 드래그해 영구 저장하고, 별도 모달 설정창의 사이드바에서 위치·모양·기본 동작을 관리한다.

완료 기준:

- 드래그 위치가 앱 재표시·재실행·크기/보기 변경 뒤에도 가까운 화면 가장자리·모서리를 유지하며 복원된다.
- 9방향 그림 리모컨과 저장 위치 복귀 버튼은 일회성 이동만 하고, 직접 드래그만 영구 위치를 바꾼다.
- 60/70/80/100/125/150/200% 전체 배율과 모든 기존 설정을 새 별도 설정창에서 사용할 수 있다.

## 2. 범위

이번에 할 것:

- Core에 3×3 앵커·여백·화면 안 보정 기반의 순수 위치 모델/계산을 추가하고 단위 테스트한다.
- Native에 모니터 장치명과 작업 영역을 제공하는 최소 경계를 추가하며, App에서 물리 픽셀 작업 영역을 WPF 논리 좌표로 변환한다.
- JSON 설정을 새 영구 위치 모델과 60/70% 유효 배율로 마이그레이션한다.
- 기존 `Popup`을 소유 오버레이의 `SettingsWindow` 모달로 교체하고, 3개 사이드바 탭과 10개 위치 리모컨을 구현한다.
- 빈 배경 드래그 종료 저장·일회성 리모컨 이동·포커스 복귀·회귀 테스트 및 실제 UI 점검을 끝낸다.

이번에 하지 않을 것:

- 자동 창 배치, 수동 창 크기 조절, 가상 데스크톱별/모니터별 독립 위치 프로필, 위치 이력.
- 리모컨 클릭의 영구 위치 저장, 단축키 충돌 피드백, 전체 DPI 인식 모델의 재설계.

## 3. 접근

큰 단계:

1. **위치 계약과 Core 계산을 닫는다.** 5개 프리셋을 9개 앵커와 저장 위치/작업 영역 레코드로 대체한다. 현재 좌표에서 가까운 앵커·여백을 캡처하고, 새 크기에는 앵커 변을 유지해 복원한 뒤 안전 여백 안으로 보정한다. 구 5개 값은 첫 로드 때 대응 앵커+18px로 옮긴다.
2. **모니터 작업 영역 경계를 추가한다.** `Switchboard.Native`에 `IWorkAreaProvider`와 Win32 구현을 두고, 기존 `MonitorFromWindow`/`GetMonitorInfo`로 장치명·작업 영역을 제공한다. App은 `HwndSource` device transform으로 물리 픽셀을 WPF 좌표로 바꾸며, 장치/변환이 없으면 주 작업 영역 안으로 보정한다.
3. **설정과 ViewModel 상태를 마이그레이션한다.** `UserSettings`·`MainWindowViewModel`·JSON 테스트를 새 저장 위치에 맞춘다. `60/70/80/100/125/150/200%`는 보존하고 구 `50/90/120%`만 가장 가까운 값으로 옮긴다. 리모컨 임시 위치는 영구 설정과 분리한다.
4. **별도 설정창을 구현하고 기존 설정을 재배치한다.** `SettingsWindow.xaml`은 `위치와 이동 / 모양과 크기 / 기본 동작` 사이드바와 오른쪽 전면 교체 콘텐츠를 소유한다. 기존 `Popup`을 제거하고 소유 모달·X/Esc·닫기 뒤 포커스 복귀를 연결한다. 모든 기존 설정과 9방향 그림/저장 위치 복귀를 각 탭에 넣는다.
5. **드래그/리모컨 런타임을 연결한다.** 상호작용 요소를 제외한 헤더·콘텐츠 배경·목록 빈 여백에서만 `DragMove()`를 시작한다. 드래그 종료만 위치를 저장하고 레이아웃 계산은 저장값을 덮어쓰지 않는다. 리모컨은 일회성 이동이며 저장 위치 복귀는 마지막 드래그 값을 적용한다.
6. **회귀와 실제 UI를 검증하고 종료한다.** 위치 계산·JSON·ViewModel 단위 테스트를 갱신했고, 2026-08-14 Release 빌드는 경고·오류 0개 및 57개 테스트 통과를 확인했다. 실제 UI 확인은 기존 실행 중인 Debug 앱을 건드리지 않기 위해 사용자 점검으로 남긴다.

중요한 판단 기준:

- Core는 WPF/Win32 없이 논리 좌표만 계산한다.
- Native는 물리 작업 영역만, App은 DIP 변환과 `Window.Left/Top` 적용만 담당한다.
- 저장 장치가 없거나 화면 밖이면 보이는 작업 영역으로 안전하게 보정한다.
- 레이아웃 재배치는 저장하지 않고, 드래그 종료만 영구 위치를 저장한다.

## 4. 검증

통과해야 할 확인:

- `dotnet build Switchboard.slnx --nologo` 및 `dotnet build Switchboard.slnx -c Release --nologo`가 경고·오류 없이 통과한다.
- `dotnet test Switchboard.slnx --nologo` 및 Release 테스트가 통과한다.
- Core 테스트는 9개 앵커, 여백 유지, 크기 확대 시 우/하단 고정, 경계 보정, 없는 모니터의 주 작업 영역 폴백, 구 5개 프리셋 마이그레이션을 다룬다.
- App 테스트는 60/70% JSON 왕복과 정규화, 드래그 저장만 영구 설정을 바꾸는지, 리모컨 복귀/일회성 이동이 저장값을 보존하는지 다룬다.
- 실제 UI에서 설정창 모달·사이드바·10개 리모컨·드래그 저장·재실행 복원·60/70/100/200%·Grid/Compact/List·X/Esc·기존 카드/검색 클릭을 확인한다.

## 5. 남는 리스크

주의할 점:

- WPF는 기본적으로 시스템 DPI 인식이며, Win32 작업 영역은 물리 픽셀이다. 변환 계약을 통합 테스트로 확인하지 않으면 혼합 DPI 모니터에서 위치 오차가 날 수 있다.
- 설정창을 `ShowDialog()`로 열면 오버레이 포커스가 닫은 뒤 사라질 수 있으므로, 닫기 뒤 오버레이 활성화·목록 포커스 복귀를 실제 UI에서 확인해야 한다.

후속으로 넘길 것:

- 모니터별 독립 위치 프로필, 위치 초기화 UI, 단축키 충돌 안내, Per-Monitor DPI-aware 앱 전환은 이번 완료 기준 밖이다.
